# 제주머니 — dev3 통합본

제주데이터허브 608번의 **2016년 9월~2017년 11월 관광객 카드 결제 건수**를 비교하는 웹앱입니다. 제주시·서귀포시 구도심, 내국인·중국인 관광객의 15개월·120개 토·일 관측 행을 포함합니다. 도민 전체 소비나 현재 매출 자료가 아닙니다.

- `dev2`의 제주 풍경 화면, 전체 기간 데이터, 가져오기·버전 검증을 유지했습니다.
- `dev1`의 NVIDIA 도구 선택, 후속 질문 조건 유지, 여러 집단의 공통 월 비교를 TypeScript 분석 서비스로 통합했습니다.
- 질문과 직접 선택 모두 `/api/compare`를 호출하며 **하나의 계산 함수**를 사용합니다. 모델은 계산하지 않습니다.
- 기본 화면에는 로그인·결제 메뉴가 없습니다. API 키와 DB 없이 바로 실행할 수 있습니다.

## 실행

검증 환경: Windows, Node.js 24.19.0, pnpm 12.21.0. 프로젝트 **최상위 폴더**에서 실행합니다. 이전 `jproject/`를 따로 지정하지 않습니다.

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

[http://localhost:3000](http://localhost:3000)에서 시작하고, `/compare`에서 질문 또는 조건을 입력합니다. Windows에서 확인된 빌드 호환성을 위해 개발·빌드 명령에 `--webpack`을 사용합니다.

```powershell
pnpm test
pnpm typecheck
pnpm build
pnpm start --port 3106 --hostname 127.0.0.1
```

실행 중인 테스트 서버에 대해 다른 창에서 `pnpm test:smoke`를 실행하면 실제 HTTP 경로를 확인합니다. 서버 주소가 다르면 `SMOKE_BASE_URL`을 설정합니다. 이 스크립트는 localhost만 허용합니다.

## 질문 예시

1. `17년 11월 제주시 내국인 토·일 결제 건수 비교` → 토요일 13,502건, 일요일 13,214건, 차이 **+288건**.
2. `그 차이가 매달 비슷했어?` → 직전 조건의 월별 수치. 한 달이면 여러 달의 경향을 판단할 수 없다고 안내.
3. `그럼 서귀포는?` → 기간·관광객·월별 분석을 유지하고 지역만 변경. 차이 **+998건**.
4. `두 구도심 내국인과 중국인 주말 소비를 비교해줘` → 네 조합의 **공통 비교월**로 집계. 직접 선택 화면의 체크박스로도 같은 비교 가능.
5. `16년 3월부터 17년 1월까지 제주시 내국인 비교` → 요청 범위를 표시하고 실제 자료가 있는 2016-09~2017-01만 계산.
6. `어느 달까지 볼 수 있어?` → 선택 조합 전체의 실제 비교 가능 월 확인.
7. `올해도 그래?` → 현재 연도의 자료 유무 확인. 2017년을 현재 자료처럼 바꾸지 않음.

각 월에서 토·일 값이 각각 하나씩 유효해야 포함합니다. 0건은 유효하며 누락·중복·형식 오류는 제외 이유를 보여줍니다. 금액·일평균·개별 매장·시간대·미래 예측은 이 통합 화면에서 제공하지 않습니다. 자료에 없는 지표는 추정하지 않습니다.

## 선택 설정

`.env.example`의 이름만 참고해 `.env.local` 또는 서버 환경변수에 값을 넣습니다. 실제 값은 Git에 추가하지 않습니다.

| 설정 | 활성화되는 기능 |
| --- | --- |
| 설정 없음 | 120행 파일을 이용한 직접 선택·기본 한국어 질문·월별·여러 조합 비교 |
| `NVIDIA_API_KEY` | NVIDIA의 분석 도구·조건 선택. 실패하면 기본 질문 해석으로 전환하고 표시 |
| `NVIDIA_MODEL` | 선택 모델. 비어 있으면 dev1 기본 모델 사용. 502/503/504 시 기본 모델로 한 번 재시도 |
| `DATABASE_URL` | 활성 DB 버전 조회. 연결 실패 시 내장 파일로 전환하며 고정 안내 표시 |
| DB + `BETTER_AUTH_SECRET` 32자 이상 + `BETTER_AUTH_URL` | 선택적 계정·본인 질문 이력. 비교 화면에는 로그인 메뉴를 추가하지 않음 |
| 위 설정 + `ADMIN_EMAILS` | `/admin` 자료 관리·원자료 가져오기. 서버에서도 권한 검사 |
| `JEJUDATAHUB_DATASET_URL`, `JEJUDATAHUB_API_KEY` | 공식 608 API 전체 페이지 수집·검증. 소개 페이지가 아닌 공식 API 엔드포인트 사용 |
| DB + 위 데이터 API 설정 + `CRON_SECRET` | 인증된 `/api/cron` 예약 갱신. 실패 시 기존 활성 데이터 보존 |
| `GEMINI_API_KEY`, `GEMINI_MODEL` | 선택적 `/api/ai/insight` 요약 API. 서버가 조건으로 재집계한 결과만 전달하며 기본 화면에서 자동 호출하지 않음 |

NVIDIA에는 질문과 지원 조건만 전달하고 키는 서버 헤더에만 넣습니다. 모델은 기본 규칙에 없는 질문 표현도 해석하고, 반복 여부를 묻는 질문에는 월별 도구를 선택할 수 있습니다. 모델 출력은 허용된 도구·지역·유형·기간인지 검증합니다. 명시한 조건과 다른 응답이나 임의 계산값은 적용하지 않습니다. 원본 오류·DB 접속정보는 응답이나 로그에 출력하지 않습니다.

계정 기능이 설정된 환경에서는 `/sign-up` 또는 `/sign-in`을 직접 방문해 가입·로그인하고 `/history`에서 **본인이 실제로 저장한 이력만** 조회합니다. 예시 결의문·기관 인증·전자서명·운영시간 권고는 제거했습니다. 관리자 이메일 등록만으로 로그인이나 권한 검증을 생략하지 않습니다.

## 선택적 DB 초기화

빈 PostgreSQL DB에 `drizzle/0001_initial.sql`을 적용한 뒤 `0002_preview_seed.sql`, `0003_analysis_context.sql` 순서로 실행합니다. 기존 DB에는 계정 테이블을 지우지 않고 필요한 스크립트만 적용합니다.

`0002`는 내장 파일과 동일한 **120행**을 넣습니다. 트랜잭션·잠금·행 수 검사를 사용하며 재실행 시 중복 적재하지 않습니다. 이전 12행 미리보기 버전은 전체 기간 버전으로 전환하지만 이미 활성화된 제공기관/관리자 버전은 대체하지 않습니다. `0003`은 질문 이력의 여러 조합·분석 종류·원래 요청 기간을 보존하는 열을 추가합니다.

데이터 파일이 바뀌면 `pnpm data:seed`로 검증 후 초기화 SQL을 다시 생성합니다. DB 초기화는 자동 실행하지 않습니다.

## Vercel

Framework는 Next.js, Root Directory는 저장소 최상위(빈 값 또는 `.`), 빌드 명령은 `pnpm build`를 사용합니다. 예전 프로젝트 설정의 Python 빌드·`jproject` Root Directory는 통합본의 설정과 다르므로 재연결할 때 확인합니다. 환경변수 변경 후에는 다시 빌드해야 합니다. 이 브랜치를 올리는 작업에서는 기존 운영 사이트의 설정·배포를 변경하지 않습니다.

## 구조와 검증 범위

- `app/`, `components/`: 제주머니 화면과 서버 API.
- `lib/jeju/`: 공통 계산·질문 해석·NVIDIA 도구 선택·데이터 검증·갱신.
- `public/jeju-weekend-608.json`: 출처가 표시된 15개월·120행 내장 데이터.
- `tests/`, `scripts/smoke-test.mjs`: 수치·후속 질문·누락/중복·AI 실패·실제 HTTP 검증.
- `legacy/dev1/`: 기존 FastAPI·DuckDB·NVIDIA 원본. 통합 앱 실행에 Python은 필요하지 않음.
- `legacy/dev2-docs/`: 변경 전 PRD·디자인 문서의 보관본. 현재 동작은 이 README와 통합 명세를 기준으로 확인.

세부 채택 근거와 한계는 [통합 명세](docs/INTEGRATION.md)를 참고하세요. 실제 외부 API·계정 DB 연결은 발급받은 비공개 설정을 넣은 환경에서 별도로 확인해야 하며, 키 없이 실행하는 검증에는 모의 NVIDIA 응답을 사용합니다.

자료 출처: [제주데이터허브 608](https://jejudatahub.net/data/view/data/608). 재배포·이용조건은 제공기관의 조건을 확인해야 합니다.
