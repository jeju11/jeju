# 제주 주말소비 PRD

## 1) 목표와 성공조건

제주시·서귀포시 구도심 소상공인과 상인회 담당자가 제주데이터허브 608번 자료로 **토요일과 일요일의 카드 결제 건수**를 비교한다. 질문을 입력하거나 지역·관광객 유형·기간을 직접 선택하면, 어느 요일이 몇 건 더 많았는지와 그 계산에 포함된 월을 한 화면에서 확인할 수 있다.

원자료에서 월별 토·일 기록을 직접 짝지어야 하는 작업을 줄이고, 사용자가 회의에서 비교 조건과 숫자의 근거를 설명할 수 있게 한다.

- 기본 비교는 비로그인 상태에서 사용할 수 있다. 이메일 계정은 질문 이력에, 관리자 권한은 데이터 운영에 사용한다.
- 조회 대상은 제주시·서귀포시 구도심과 내국인·중국인 관광객이다. 지표는 카드 결제 건수이며 표시는 건 단위다.
- MVP 범위 밖에는 서비스 내 결제·구독, 매출액·평균 결제액 분석, 업종·매장·연령·시간대 분석, 실시간 실적과 미래 예측이 있다.

| 계산 근거 | 현재 데이터의 관측 기간, 비교에 사용한 데이터 출처, 계산 방식, 제외된 월과 사유를 펼쳐 확인할 수 있다. |

## 4) 기능 명세

### 질문 해석과 조건 확정

1. 한국어 질문을 규칙으로 해석해 요일 비교, 월별 추이, 조회 가능 기간 확인 중 하나를 실행한다. 현재 앱의 비교에는 외부 생성형 AI 호출이 필요하지 않다.
2. 명시한 지역·관광객 유형·기간을 먼저 적용한다. 새 질문에서 빠진 항목은 화면의 선택값을 사용한다. “그럼”, “그 차이” 등 후속 질문은 직전 성공 조회의 조건을 이어받고, 새로 명시한 조건만 바꾼다.
3. `2017년 11월`, `17년 11월`, `2017-11`을 같은 월로 읽는다. 한 달을 지정하면 시작월과 종료월을 같은 값으로 설정한다. 두 날짜를 지정하면 입력 순서대로 시작월과 종료월을 적용한다. `2017년 4월부터 6월까지`처럼 두 번째 달의 연도를 생략하면 앞에 명시한 연도를 사용한다.
4. 요청 기간이 공식 수집 기간과 일부만 겹치면 질문 입력에서는 겹치는 범위를 적용한다. 시작·종료월은 모두 포함한다. 직접 선택에서는 공식 수집 기간 안에서 월을 고른다.
5. 질문을 실행하면 실제 적용된 지역·관광객·시작월·종료월이 직접 선택 항목에도 반영된다. 직접 선택 버튼을 누르면 현재 선택값만으로 결과를 계산한다.

### 자료와 집계

- 필수 자료는 제주데이터허브 608번이다. 앱은 `districtType`, `userType`, `dtYearMonth`, `dtWeek`, `useCount`를 사용한다. [제주데이터허브 608번](https://jejudatahub.net/data/view/data/608) · [공공데이터포털 카드 데이터 설명](https://www.data.go.kr/data/15094893/openapi.do)
- 내장 파일 `public/jeju-weekend-608.json`에는 2016년 9월~2017년 11월의 토·일 관측 **120행**이 들어 있다. 두 지역과 두 관광객 유형 각각에서 15개월을 비교할 수 있다.
- 선택한 지역·관광객 유형에서 토요일과 일요일의 유효한 건수가 각각 한 행씩 있는 월만 합계에 포함한다. 0은 유효한 건수다. 포함된 월의 토요일과 일요일 건수를 각각 합산하고, 차이는 **토요일 건수 − 일요일 건수**로 계산한다.
- 월별 추이는 월마다 계산한 차이를 표에 보여주고, 여러 달이 있으면 가장 작은 차이와 가장 큰 차이를 요약한다. 조회 가능 기간 질문은 해당 조합에서 유효한 토·일 쌍이 있는 최신 월을 표시한다.

### 계정과 데이터 운영

- 비교 화면은 내장 JSON으로 집계한다. 서버의 비교 요청은 활성 DB 데이터 버전을 읽을 수 있고, 활성 버전이 없거나 조회할 수 없으면 내장 자료를 사용한다. 비교 화면에 표시되는 집계는 내장 JSON 버전을 따르므로, 관리자에서 적용한 새 DB 버전을 화면의 데이터와 동기화하는 작업은 남아 있다.
- 로그인 사용자가 조회에 성공하면 질문·적용 조건·조회 시각을 계정별로 저장하도록 구현돼 있다. 이력의 재조회는 본인 항목만 허용한다.
- 관리자는 608번의 JSON 또는 CSV를 선택하고, 유효 행 수·관측 범위·토·일 쌍이 있는 월·검증 오류를 미리 본 뒤 적용할 수 있다. 일부 월만 가져오면 같은 관측 키를 갱신하고 다른 달의 데이터를 보존한다.
- API 갱신 코드는 전체 페이지 수집과 검증을 마친 자료만 새 DB 버전으로 활성화한다. 예약 설정은 매주 월요일 09:00 UTC이며, 실행에는 환경 설정과 제공기관 접근이 필요하다. 운영 환경의 실제 자동 갱신 성공은 확인이 남아 있다.

## 5) 예외 처리

| 상황 | 판단과 처리 |
| --- | --- |
| 빈 질문 | 공백을 제외한 질문이 비어 있으면 현재 직접 선택 조건으로 비교한다. |
| 질문에서 조건을 읽을 수 없음 | 지역·관광객·날짜 또는 지원하는 비교 표현을 찾을 수 없으면 입력 예시를 안내한다. 같은 화면에서 직접 선택을 사용할 수 있다. |
| 연도가 모호함 | “11월 비교”처럼 수집 기간에 같은 달이 두 해에 있으면 연도를 함께 입력하도록 안내한다. |
| 유효하지 않은 월 | `17년 13월`처럼 월이 1~12를 벗어나면 입력 오류로 표시하고 집계를 중단한다. |
| 범위의 한쪽만 입력함 | “17년 4월부터”처럼 기간을 뜻하는 표현과 한 달만 들어 있으면 시작월과 종료월을 함께 입력하도록 안내한다. |
| 기간 순서가 역전됐거나 날짜가 세 개 이상임 | 시작월이 종료월보다 늦으면 기간 순서를 확인하도록 안내한다. 월을 세 개 이상 명시하면 시작월·종료월 두 개를 요청한다. |
| 요청 기간이 일부만 자료 범위와 겹침 | 자연어 질문이면 요청 기간을 보존한 채 공식 수집 기간과 겹치는 범위로 집계한다. 결과에 두 기간을 모두 표시한다. |
| 요청 기간 전체가 자료 범위 밖임 | 공식 수집 기간을 안내하고 집계를 중단한다. 이번 주말·오늘 등 현재 실적을 묻는 경우에도 조회할 연도·월을 안내한다. |
| 해당 월 자료가 없거나 한 요일이 누락됨 | 그 달을 토·일 양쪽 합계에서 제외한다. 관측 행 없음 또는 누락된 요일을 사유로 표시한다. 0건이 기록된 행은 포함한다. |
| 중복 또는 건수 오류가 있음 | 같은 월과 요일에 여러 행이 있거나, 건수를 유효한 0 이상의 정수로 읽을 수 없으면 해당 월을 제외하고 사유를 보여준다. |
| 비교 가능한 달이 0개 또는 1개임 | 0개이면 비교 가능 월이 없다는 안내와 제외 사유를 표시한다. 1개로 월별 변화를 물으면 그 달의 수치는 제시하되 월별 유사성은 판단할 수 없다고 안내한다. |
| 내장 데이터 파일 읽기 실패 | 결과 영역에 오류 안내와 다시 시도 버튼을 표시한다. 입력창과 직접 선택값은 유지된다. |
| 관리자 권한 또는 업로드 검증 실패 | 관리자 권한이 없으면 서버에서 거부한다. 지원 형식 오류, 중복 또는 유효하지 않은 관측이 발견되면 적용을 중단한다. |
| API 갱신 실패 | 마지막 활성 DB 버전을 유지하고 관리자 화면에 실패 사유를 표시한다. 실패한 갱신은 성공으로 기록하지 않는다. |

### 운영 적용 전 확인할 조건

- [ ] 같은 조건을 질문 입력과 직접 선택으로 실행했을 때 요일별 합계, 차이, 월별 표가 일치한다. 여러 달의 표를 합산하면 기간 합계와 일치한다.
- [ ] 첫 비교 → 월별 추이 → “그럼 서귀포는?”을 한 흐름으로 시연하고, 마지막 조회에서 지역만 변경되는지 확인한다.
- [ ] 390px 모바일과 데스크톱에서 입력, 비교 결과, 오류 안내를 읽을 수 있다.
- [ ] 평가 환경에서 가입·로그인·본인 이력 재조회, 일반 계정의 관리자 접근 차단, 관리자 파일 검증·적용 흐름을 확인한다.
- [ ] 운영 환경에서 예약 갱신 성공·실패, 새 DB 버전의 적용 범위와 실패 시 기존 버전 보존을 확인한다.
- [ ] 수정본을 운영에 배포한 뒤 실제 배포 주소에서 기간 질문을 다시 검증한다. 이 문서의 검증 기록은 v0 미리보기 기준이다.
