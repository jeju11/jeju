# 제주 주말소비

제주데이터허브 데이터 608의 과거 관측치를 사용해 제주시·서귀포시 구도심의 토요일과 일요일 카드 결제 건수를 비교하는 Next.js 앱입니다. 비교는 비로그인으로도 가능하며, 계정은 성공한 질문 이력 저장에 사용합니다. 결제/상품 기능은 포함하지 않습니다.

## 필요한 설정

- Neon `DATABASE_URL` — 연결된 Neon 통합에서 제공됩니다.
- `BETTER_AUTH_SECRET` — Better Auth 세션 서명용 무작위 값(최소 32자).
- `ADMIN_EMAILS` — 관리자 권한을 부여할 이메일 주소의 쉼표 구분 목록.
- `JEJUDATAHUB_DATASET_URL` — 데이터 608의 HTTPS API 엔드포인트 URL(HTML 소개 페이지가 아니라 실제 API 주소).
- `JEJUDATAHUB_API_KEY` — 제주데이터허브 API 키. 서버에서만 사용하며 브라우저로 전달하지 않습니다.
- `CRON_SECRET` — 예약 갱신 요청을 보호하는 무작위 bearer secret.

앱 코드와 예제 설정에는 실제 키나 비밀값을 넣지 마세요. Vercel 환경 변수는 프로젝트 Settings의 Vars에서 설정합니다. API 키와 URL은 제주데이터허브가 발급한 연동 문서의 주소와 인증 방식에 맞춰 설정해야 합니다. 현재 갱신 요청은 `Authorization: Bearer`와 `X-API-Key` 헤더를 보내며, JSON 배열/`rows`/`data` 응답 또는 CSV를 읽습니다. 페이지네이션은 같은 HTTPS 호스트의 다음 페이지 URL을 지원합니다.

## 데이터베이스 초기화

Neon 데이터베이스에 `drizzle/0001_initial.sql`의 각 SQL 문을 한 번에 하나씩 적용한 다음 `drizzle/0002_preview_seed.sql`을 실행합니다. 초기화 스크립트는 Better Auth 테이블, 버전별 관측 데이터, 사용자별 질문 이력, 갱신 기록 및 인덱스를 준비합니다. 시드 스크립트는 제공된 12개 관측 행을 `preview-2017-11-v1` 버전으로 추가하며, 해당 버전이 이미 있으면 행을 중복 추가하지 않습니다.

현재 연결된 Neon 프로젝트에는 위 구조가 생성되어 있고 미리보기 버전의 12개 행이 이미 적재되어 있습니다. 화면은 활성 DB 버전을 사용하며 DB를 읽을 수 없거나 활성 버전이 없으면 같은 집계 로직으로 내장 `lib/jeju/preview-data.ts` 데이터를 사용합니다. `lib/db/schema.ts`는 앱 쿼리의 타입 정의이며, DB 구조 변경은 SQL 스크립트에도 반영해야 합니다.

## 실행

Node.js 20 이상과 pnpm을 사용합니다.

```bash
pnpm install
pnpm dev
```

`BETTER_AUTH_SECRET`은 로그인/가입 테스트 전에 설정해야 합니다. 로그인은 이메일과 비밀번호를 사용합니다. 첫 계정은 일반 계정이며, `ADMIN_EMAILS`에 해당 이메일이 포함된 계정만 관리자 페이지와 수동 갱신을 사용할 수 있습니다.

## 자동·수동 갱신

- 관리자는 `/admin`에서 수동 갱신을 시작하고 활성 버전, 행 수, 실제 관측 기간, 최근 실행 결과와 실패 사유를 확인할 수 있습니다.
- `vercel.json`은 매주 월요일 09:00 UTC에 `/api/cron`을 실행하도록 설정합니다. 예약 실행에는 `CRON_SECRET`이 필요합니다.
- 갱신은 전체 페이지를 수집하고 필수 필드가 검증된 뒤 새 버전과 모든 관측 행을 한 트랜잭션으로 저장하고 활성화합니다. 실패하면 기존 활성 데이터는 유지됩니다.
- 데이터 갱신은 실제 API URL과 키가 설정되어야 실행됩니다. 잘못된 키/응답을 사용할 때는 관리자 화면의 실패 사유를 확인하세요.

## 확인 시나리오

1. 비로그인 상태에서 빠른 예시를 실행합니다. 2017년 11월 제주시 구도심 내국인은 토요일 13,502건, 일요일 13,214건, 차이 `+288건`이어야 합니다.
2. 질문에 `그럼 서귀포는?`라고 입력합니다. 직전 조건의 관광객과 기간은 유지하고 지역만 바뀌어 `+998건`이어야 합니다. 직접 선택으로 제주시/서귀포시 및 관광객/기간을 바꿔도 같은 API 집계 결과를 사용합니다.
3. 제주시 내국인 2016년 9월–2017년 11월을 선택하면 파일에 포함된 2016년 9월 `+402건`, 2016년 10월 `-354건`, 2017년 11월 `+288건`만 포함되고 나머지 월은 미포함 사유가 나와야 합니다.
4. 2017년 11월 제주시 중국인은 `-73건`, 서귀포시 내국인은 `+998건`, 서귀포시 중국인은 `-7건`입니다. 토·일 중 하나가 빠진 달, 중복 또는 형식 오류가 있는 달은 월별 표 합계에서 제외됩니다. `0`은 유효한 값입니다.
5. 시작월이 종료월보다 늦거나 공식 수집 기간 밖인 입력은 오류 상태를 표시하고 입력을 유지해야 합니다. 데이터가 없는 조합은 결과 없음과 제외 사유를 표시합니다.
6. 가입 후 성공한 비교를 실행하고 `/history`에서 확인합니다. 새로고침/재로그인 후에도 해당 계정의 이력만 보여야 하며, 이력 선택 시 같은 조건을 다시 조회합니다.
7. `ADMIN_EMAILS`에 없는 로그인 계정은 `/admin`에서 접근이 거부되어야 합니다. 허용된 계정은 수동 갱신이 가능하며, 실패해도 기존 버전과 비교가 유지되어야 합니다.
8. UI는 390px 너비와 데스크톱에서 확인합니다. 인증·DB·갱신을 설정하지 않은 환경에서도 내장 미리보기로 비교 화면을 열 수 있어야 합니다.

```bash
pnpm exec tsc --noEmit
pnpm build
```
